# Avatar

A person's face: their picture, or their initials on a colour that is
theirs, or — when there is no name to take initials from — a silhouette.
An agent's face is a robot on lime.

<Canvas of={AvatarStories.Sizes} />

## When

- Anywhere a person appears at a glance: a row, a card, a picker, a byline.
- The scale is 16 · 18 · 20 · 24 · 32 · 36 (default): 18 in a group's reply
  row, 20 in a **Person**. Pick from it rather than inventing sizes.

## When not

- Several people at once → **AvatarGroup**.
- The face beside a name, with nothing else on the line → **Person**. A byline
  that sets the name its own way — bold, with a time — is an Avatar beside its
  own text.
- The face as a button that opens a menu → **PersonTrigger**.

## How

```tsx
import { Avatar } from '@estiva-app/ui'

<Avatar name={person.name} src={person.picture} size={24} />
```

- The caller resolves `src`. While the picture loads the tile stays empty;
  once it arrives it fills the tile; if it fails, the initials show — nothing
  to handle. It is Base UI's `Avatar`, which watches the picture load.
- Initials come from a **name, never a key**: the first letter of the first
  two words, skipping words that open with a symbol. An unnamed person is
  the silhouette, not a `?` — a question mark reads as an error badge.
- The initials are centred on the capitals themselves — cap height to
  baseline — not on the line of text around them. A single face can
  still sit up to half a pixel off: the screen rounds text to its pixel grid
  wherever the tile lands.
- The colour behind initials is per person, chosen from the name, the same
  everywhere they appear. It is a fallback palette, not a token — themes
  have no say in it.
- The corner is `rounded-sm` and stays that way. A surface that wants
  rounder geometry wraps the Avatar concentrically — it does not override
  the Avatar's own radius.

### What it says out loud

**A face is silent by default**, and that is the important half: almost every
face in the suite sits beside the name it belongs to — in a `Person`, in a
`MenuItem`'s `leading`, in a row — and a picture that spoke there would say the
name twice. It used to: a `Person`
inside a button announced **"AD Ana Duarte"** (the initials read as text), and
with a picture **"Ana Duarte Ana Duarte"**.

**`label` names a face that stands on its own** — the compact `PersonTrigger`,
a stack of members — and the tile becomes one image with one name.

```tsx
<Avatar name={person.name} />                     {/* beside a name: silent */}
<Avatar name={person.name} label={person.name} /> {/* alone: says who it is */}
```

### An agent

**`bot` draws a robot on lime** in place of the initials, for a profile that
says it is an agent (NIP-24's `bot: true`, which Estiva ID publishes for every
agent). Its picture still wins when it has one.

```tsx
<Avatar name={profile.name} src={profile.picture} bot={profile.bot} />
```

- Take `bot` from the profile, **never from the name**: "steered by" is a
  name, not a marker.
- Lime is the same in every theme, on the initials' light and shade. No
  person's colour is near it, so an agent never reads as a person, nor as the
  yellow urgent mark.
- The robot is drawn at 5/8 of the tile, larger than the silhouette, so it
  still reads at 16px.
- Every part that draws a face takes `bot` with the person: `Person`,
  `PersonTrigger`, `AvatarGroup`, `MembersPill`, `MembersDialog`, the mention
  menu, a comment's and a reply's author, and the link parts.

- `initialsFor(name)` and `hueFor(name)` give the same initials and colour where
  the part itself cannot be drawn.

## What it owns

It does these by itself. Write none of them around it.

| It does | So you never write | Refused when written by hand |
|---|---|---|
| Shows initials from the name when there is no picture, or when it fails to load | an `onError`, or initials of your own |  |
| Shows a robot for an agent (`bot`) when there is no picture | a robot icon of your own, or a check of the name |  |
